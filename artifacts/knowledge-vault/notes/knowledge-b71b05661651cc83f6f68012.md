## Functional explanation

Status: **documented**

Role: custom&#95;storage&#95;read&#95;policy

This machine Custom Deny&#95;Read key is the policy container for denying read access to administrator-selected removable-storage classes. Microsoft maps the same-named enable value here. A preserved Microsoft-authored historical ADMX template separately places selected classes in a List child. The key, enable value, and class list are distinct objects; interpreting the final path component as a scalar value would lose this distinction.

## Atomic claim

Stores the machine custom-class removable-storage read restriction and its class-list child.

Scope: **machine**

## Meaning in system-level logs

For a logged target, distinguish the Deny&#95;Read key, its Deny&#95;Read enable value, and entries below List. Inspect complete path, value data, operation, and result; actual blocked storage read operations need device and access-outcome evidence.

### What the path cannot establish

- The key alone does not establish enablement or identify the selected classes.
- A policy change does not establish that a device read request was made or denied.
- The historical ADMX layout does not guarantee identical list encoding in every Windows release.

### Applicability

The referenced ADMX CSP tables list device scope on Pro, Enterprise, Education, and IoT Enterprise: Windows 10 2004/20H2/21H1 with KB5005101, and Windows 11 21H2 or later. These are CSP delivery baselines; they do not date the introduction of the underlying Group Policy setting. The separately reviewed preserved ADMX declares schema/revision 1.0 and Windows Vista support; its List layout is historical evidence, not a universal version guarantee.
